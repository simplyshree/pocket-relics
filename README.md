# Pocket Relics

Build a polished, quirky, highly replayable web game called “Pocket Relics”.

Pocket Relics is a collection of extremely short 20–60 second mini-games where every play session creates a unique tiny digital souvenir that the player gets to keep.

The core feeling should be:

“what tiny weird thing will I get today?”

It should feel like opening a capsule toy, finding something in a thrift shop, collecting travel souvenirs, and playing a tiny internet game — all at once.

The experience should be:

cute

nostalgic

quirky

slightly mysterious

aesthetically beautiful

relaxing

funny

instantly understandable

very fast

collectible

highly shareable

Do NOT make this a complicated game.

The player should be able to open the website, play something, receive a souvenir, and save it to their collection in under one minute.

CORE CONCEPT

Every time the user plays, they complete a tiny random activity.

Their choices create a unique souvenir.

THE COLLECTION

The player's saved souvenirs should appear inside a beautiful page called:

“MY CABINET”

or

“THE LITTLE MUSEUM”

Do NOT make it look like a traditional inventory grid.

Make it feel like a personal curiosity cabinet.

Imagine:

wooden shelf
scrapbook
bedroom wall
museum display
travel journal

combined into one digital collection.

Items can sit on:

shelves
tiny frames
hooks
display stands
pinboards

Different souvenir shapes should look visually different.

Examples:

a motel key hangs from a hook

a postcard sits behind another postcard

a snow globe sits on a shelf

a ticket is pinned to cork

a cassette lies horizontally

a coin rests inside a tiny tray

Make browsing your collection satisfying.

Suspicious

MOBILE EXPERIENCE

Mobile should be the main priority.

A person should be able to:

open website

play with one thumb

receive object

share it

within approximately 30 seconds.

Use large touch targets.

Avoid tiny text.

Animations should remain smooth.

Do not create pages requiring complex scrolling.

TECHNICAL APPROACH

Use React + TypeScript.

For MVP, avoid requiring accounts.

Use localStorage to save:

collection

favorites

streak

statistics

settings

daily encounter completion

relic metadata

Structure code so Supabase can later support:

accounts

cloud collections

public cabinets

friend challenges

rare global events

shared relic links

global collection statistics

But do NOT overengineer the MVP.

MVP GAMES

Initially build ONLY five functional encounters:

Mystery Vending Machine

Strange Motel

Pick A Door

Fortune Machine

Lost & Found

Each should take approximately 15–45 seconds.

Every game must create a visually distinct souvenir.

MVP SOUVENIRS

Implement:

drink can

motel key

postcard

mystery object card

IMPORTANT DESIGN PRINCIPLE

Do NOT make the user feel like they need to “win.”

There is no losing.

The reward is:

curiosity

surprise

humor

aesthetic satisfaction

collecting

sharing

The emotional loop should be:

“what is this?”

↓

“hehe”

↓

“that's cute”

↓

“I'm keeping that”

↓

“wait I want another one”

LONG-TERM PRODUCT FEELING

After using Pocket Relics for several months, a person's cabinet should feel like a strange visual diary of tiny moments.

Someone should be able to scroll through it and remember:

“oh, I got this weird motel key that night.”

“this was my first rare relic.”

“my friend and I both did this one.”

“why do I have nine frogs?”

The collection itself should gradually become more meaningful than the individual games.

That is the heart of the product.

Build the MVP around this idea:

Every tiny moment leaves behind a tiny souvenir.
